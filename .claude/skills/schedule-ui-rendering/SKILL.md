# 스케줄 UI 렌더링

산출물은 일정표 문서가 아니라 **오늘 무엇을 몇 페이지 녹음할지 즉시 알려주는 도구**다. 그 기준으로 화면 요소를 판단한다.

## 착수 조건

1. `_workspace/03_validator_report.md` 가 **FAIL 0** 임을 확인한다. 틀린 일정을 예쁘게 보여주는 것이 이 파이프라인에서 가장 나쁜 결과다.
2. UI 작성 전 `artifact-design` 스킬을 로드한다. 사용자가 매일 여는 화면이므로 설계 투자 판단이 필요하다.

## 데이터를 UI에서 재계산하지 않는다

누적 진도, 일일 총량, 마감 마일스톤은 스케줄 JSON에 이미 들어 있다. UI에서 다시 계산하면 최적화 단계의 숫자와 어긋날 수 있고, 그 불일치는 사용자가 발견하기 전까지 드러나지 않는다. JSON 값을 그대로 인라인한다.

## 반드시 화면에 있어야 하는 것

| 요소 | 왜 |
|------|-----|
| 주간 캘린더 (월~금 격자) | 하루 칸에서 배치 도서·페이지·일일 총량이 한눈에 들어와야 한다 |
| 일일 상한 대비 부하 게이지 | 숫자만 나열하면 제약이 지켜졌는지 알 수 없다. 상한 대비 위치를 시각화한다 |
| 전일 점유일의 시각적 구분 | 전일 녹음/편집은 페이지 개념이 없는 다른 종류의 날이다. 색·형태로 확실히 구분한다 |
| 도서별 진도 (누적/전체) | 뒤처졌는지 여부는 하루 단위로는 보이지 않는다 |
| 마감 마일스톤 | 각 도서의 마감일과 계획 완료일을 나란히 보인다 |
| 타협 지점 표시 | 단일 도서 구간, 상한 근접일은 화면에 표시하고 이유를 붙인다 |

## 도서별 색상

도서마다 고정 색을 배정하고 캘린더·진도바·범례에서 동일하게 쓴다. 색이 흔들리면 격자를 훑을 때 도서를 구분하는 비용이 커진다. 색상 선택과 대비 검증은 `dataviz` 스킬의 팔레트 규칙을 따른다.

## 기술 제약

- 자기완결형 단일 HTML. 인라인 CSS/JS. 외부 리소스는 Google Fonts만 허용된다 (그 외 CDN·원격 이미지는 CSP에 차단된다).
- 라이트/다크 양쪽에서 읽혀야 한다. 토큰을 맨 `:root` 에 정의하고, `@media (prefers-color-scheme: dark)` 와 `:root[data-theme="dark"]` 양쪽에서 재정의한다.
- 캘린더 격자는 좁은 화면에서 자체 `overflow-x: auto` 컨테이너 안에서 스크롤한다. 페이지 본문이 가로 스크롤되면 안 된다.
- 파일은 프로젝트 루트 `index.html` 로 쓴다.

## 발행

`Artifact` 도구로 발행한다. **재발행은 반드시 같은 파일 경로로** 한다 — 새 경로는 새 URL을 발급받으므로 사용자가 이미 공유한 링크가 죽는다. 이전 세션의 아티팩트를 갱신할 때는 `action: "list"` 로 URL을 찾아 `url` 파라미터로 넘긴다.

## 실적 체크인을 붙일 때

화면이 계획 표시에 그치지 않고 실적을 입력받는다면, 입력·이월·진행률 규칙은
`daily-progress-tracking` 스킬이 소유한다. 여기서는 표시만 담당한다. 그 스킬을 먼저 로드하고,
런타임 저장 계약은 `artifact-capabilities` 스킬로 확인한다.

렌더링 측 규칙 세 가지:

- **계획과 실적을 같은 칸에서 대조시킨다.** 입력란 옆에 그날 목표(`/37p`)를 붙이고, 미터에
  계획 위치 표시선을 함께 그린다. 실적만 보이면 그것이 좋은 수치인지 알 수 없다.
- **입력 중에는 전체를 다시 그리지 않는다.** 재렌더는 포커스와 커서 위치를 잃게 만들어
  빠른 연속 입력을 흘린다. 파생 영역(진행률·주 헤더·주말 칸·해당 일자 미터)만 갱신하고,
  현재 포커스가 들어 있는 컨테이너는 건드리지 않는다.
- **저장 상태와 범위를 항상 표시한다.** 어디까지 저장됐는지 모르는 트래커는 쓰지 않게 된다.
  저장 시각과 함께, 유지되는 경우와 유지되지 않는 경우를 문구로 구분한다.

## 피드백 라우팅

사용자 피드백이 **표시**에 관한 것이면(색, 배치, 라벨, 강조) 여기서 처리한다. **배분**에 관한 것이면(페이지 수, 날짜, 도서 조합) `vocal-load-scheduling` 으로 넘기고 재검증까지 거친 뒤 다시 렌더링한다. **이월·진행률 규칙**에 관한 것이면 `daily-progress-tracking` 으로 넘긴다. 이 구분을 흐리면 UI에서 데이터를 손으로 고쳐 JSON과 화면이 갈라진다.
